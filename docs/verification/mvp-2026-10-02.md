## 実機条件と観察

Windows 11 x64、8 logical CPU、内蔵 AMD GPU + NVIDIA discrete GPU、OBS 32.2.2 portable / Qt 6.11.1。専用 profile・scene・録画先と GUI lease を使用しました。通常インストールと portable の配置は [使用説明](../using-monitor.md) に区別しています。

- **現在値と対象**: System CPU/RAM、OBS CPU/working set、GPU engine 使用率/専用メモリが約1秒ごとに変化。RAM は used/total GiB、OBS RAM は MiB、GPU は選択した adapter の値を表示。
- **複数 GPU**: NVIDIA と内蔵 AMD を切り替え、それぞれ別の使用量・容量を表示。内蔵 GPU の実測 `0.0%` と専用メモリ `6.7 / 485.8 MiB` を観察。NVIDIA は約 `1.0 / 15.7 GiB`。Tab と矢印キーで選択を操作。
- **テーマと配置**: OBS 標準 Stats と並置。Yami の dark 表示、設定画面で Default / Light を切り替え、背景・文字・標準バー・選択欄の追従を観察。狭幅から拡大、float/re-dock、タブ化、非表示からの再表示を確認。
- **言語と倍率**: 実 OS DPI は100%。日本語100%、英語 `QT_SCALE_FACTOR=1.5`、日本語 `QT_SCALE_FACTOR=2` を観察。数値と単位が読め、viewport より内容が高いときは縦スクロールで GPU と末尾の更新時刻へ到達。150/200%はプロセス限定 Qt スケールであり、実 OS DPI の試験ではありません。
- **再開状態**: dock 再表示・float/re-dock の直後は `計測中…` / `Collecting...` を表示し、古い fill を表示せず、新しい計測値へ復帰。
- **終了・再起動**: 日本語100%、英語150%、日本語200%の各 GUI session を通常終了。plugin の unload と OBS ログの `Number of memory leaks: 0`、プロセス消失を確認。終了時刻は23:07:33、23:14:59、23:19:49 JST。

200%起動準備で非対話デスクトップ上に生成された検証プロセスは operator が停止し、GUI session を再起動しました。この中断を正常終了の証拠には数えません。GUI 接続の再取得後、同じ候補をロードして200%表示と通常終了を観察しています。

## 録画と負荷の観察

単一 Color Source、desktop/mic mute、base 1920x1080、出力1280x720 / 30fps、x264 6000kbps のローカル録画。22:59:06.967〜23:03:18.150 JST（約251秒）で正常停止し、188,237,964 bytes の MP4 を生成しました。OBS ログは7519 output frames / 7536 drawn frames、標準 Stats は recording encoder lag `0 / 7534`、同 session の render lag `0 / 15331`（ともに0.0%）でした。各カウンターの観測時点・対象が異なるため同一分母へ置換しません。

同じ録画中、OBS process の CPU 時間差分を経過時間と8 logical CPUで割り、30秒ずつ採取しました。

- dock表示: 30.0209525秒、OBS全体CPU **0.7742%**、working set 316.78 MiB。
- dock非表示・通知dialogなし: 30.0282784秒、OBS全体CPU **0.6179%**、working set 291.68 MiB。
- 観測差: **+0.1563 percentage points**。パネル操作、更新、非表示/再開が応答し、録画を継続。

1台・短時間・単純sceneの参考値です。サンプル順序は表示→非表示、他processやUI操作の影響を除去していません。plugin単独の厳密なCPU負荷、長時間安定性、配信の測定結果として扱いません。通知dialogが開いていた別の非表示サンプルは比較から除外しました。
